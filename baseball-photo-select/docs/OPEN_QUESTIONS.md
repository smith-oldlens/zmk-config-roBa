## 実装中に確定させた仕様解釈(記録)

- **M1 / spec §4.1 のサイズ安定待ち**: 仕様は「2 秒間隔で 2 回サイズを取得」だが、
  これを全ファイルに適用すると M1 の受け入れ基準(100 枚を 5 秒以内)と両立しない。
  → `verify_file(..., wait_stable=)` を設け、**バッチ ingest(カード=静止したファイル)では
  待たず、watch モード(FTP 到着=書き込み中の可能性)では待つ**と解釈した。
  EOI マーカー検証と EXIF 読み取りは両モードとも実施するため完全性の保証は落ちない。
- **M1 / 外部ディレクトリからの取り込みは move ではなく copy**: spec §4.3 は
  「work/ へ move」と書くが、これは inbox を前提とした記述。カード(base_dir 外)を
  move するとカードから写真が消えるため、docs/01 の不変条件 3(データを失わない)を優先し、
  **base_dir 外のソースは copy、inbox 内は move** とした。
- **M1 / 隔離(quarantine)の重複防止**: カードは copy 運用のため破損ファイルが残り続け、
  再実行のたびに隔離コピーと DB 行が増える欠陥があった。**同名かつ同サイズの隔離済み
  ファイルがあればスキップ**する。副作用として「別カードの同名・同サイズの破損ファイル」は
  隔離されないが、原本はカードに残るためデータ損失にはならない。
