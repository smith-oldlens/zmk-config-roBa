# 06. 再設計: 撮影 → 自動転送 → 自動セレクト → 自動現像(2026-08)

## 目的の再定義

> 撮影 → ワイヤレステザーで iPad または Mac へ自動転送 → セレクトツールがセレクト完了 →
> 人間は「ツールが取りこぼしたもの」だけレビュー → Lightroom でまとめて現像 →
> いずれ現像も自動化。**最重要はセレクト時間の短縮。**

体験として定義し直すと:

**「試合が終わった時点で、Lightroom(と iPad)には ★付きのセレクト済みと
『要確認』の小さな山だけが並んでいて、帰りの車で iPad から要確認だけ見れば終わり。
帰宅後は現像済みのキーパーを書き出すだけ」**

## 調査の結論(3本、2026-08 実施。詳細ソースは各調査レポート)

1. **この体験を提供する製品は存在しない(空白の確認)**。
   - 商用 AI カリング(Aftershoot/FilterPixel/Narrative/LrC Assisted Culling)は全て
     「撮影後のフォルダ一括処理」。**着弾順に判定し続けるリアルタイム型は商用/OSS とも皆無**
   - 野球固有の瞬間理解・「わが子優先」も未実装(顔+背番号の PhotoShelter RosterID は法人 SaaS)
   - 入口(Sony FTP)・中間(AI カリング)・出口(LR 連携)の部品は揃っているのに
     **3 つを無人で繋いだ公開実装がない** — 本プロジェクトがまさにその糊
2. **iPad は受信サーバにしてはならない**。iPadOS はバックグラウンドでサーバソケットを
   維持できず(ShutterSnitch も「画面常時点灯」前提)、Python パイプラインも動かない。
   **iPad の正しい役割は「Lightroom クラウド経由のビューア+星付けリモコン」**
   (星は LR Classic と双方向同期される。同期はスマートプレビューなので軽い)
3. **現場にノート PC を持ち込む必要すら無くなった**。α7C II の FTP 自動転送は
   スマホ USB テザリングや SIM 入りルーターを経由でき、**Tailscale VPN で自宅 Mac に直送**
   すれば、撮影から数秒〜十数秒/枚で自宅に着弾する(上り 25-30Mbps 実測で
   JPEG 10MB ≈ 3 秒)。旧 Phase 4 の懸念(炎天下の PC・電池・盗難)は構成ごと消える
4. **自動現像の DIY 経路は技術的に成立が確認済み**。
   - Lightroom は XMP の `crs:` 名前空間(公式文書化済み)から現像設定を読む。
     条件: `crs:AlreadyApplied="False"` + 正しい `crs:ProcessVersion`。
     Aftershoot が商用でこの経路を使っており実運用の証明になっている
   - 教師データは自分の .lrcat の `Adobe_imageDevelopSettings`(SQLite)から抽出可能
     (先行 OSS 多数)。「画像埋め込み→スライダー回帰」は確立された研究分野
   - 少年野球(屋外昼間・光が安定)は**露出/WB/トーンだけで 8 割揃う**イージーケース。
     商用代替: Aftershoot EDITS $30/月・Neurapix(20 枚から学習・$0.03/枚)・Imagen $0.05/枚

## 新アーキテクチャ

```
[α7C II] ─FTP自動転送(JPEGのみ・撮影と同時)─┐
                                              │ 経路B: SIM入りルーター+Tailscale → 自宅Mac
                                              │ 経路C: Creators' Cloud → Google Drive → Mac同期フォルダ
                                              ▼
                     [自宅Mac: bps 常駐(launchd)]  inbox/ に着弾
                              │
        ①ingest(検証・AF読み出し) → ②連写グループ確定 → ③採点 → ④星確定
        → ⑤現像パラメータ予測(crs: を XMP に併記)★新規
        → ⑥deliver/ へ(星+現像設定入り)
                              ▼
              [Lightroom Classic 自動読み込み]
        スマートコレクション: 「セレクト」★3+ / 「決定的瞬間」★5 / 「要確認」★0
                              │ クラウド同期(スマートプレビュー)
                              ▼
        [iPad Lightroom] ← 帰路に「要確認」だけレビュー。付けた星はMacへ双方向還流
```

**人間の作業は「要確認バケツのレビュー」だけ**に収束する。
ツールは 3 値で出力する(ここが「取りこぼしを人が拾う」運用の核):
- **★3/★5 = 自信を持って採用**(そのまま使える)
- **★1+Purple = 自信を持って除外**(ブレ・露出破綻。見る必要なし)
- **★0 = 要確認**(判断保留。人間が見るのはここだけ)
自信の閾値を上げれば★0 が増えて安全側に、下げれば手離れが良くなる。
Phase 1 の校正で「★0 が全体の 10-20%」になるよう調整するのが目標。

## レイヤー別設計

### レイヤー1: 自動転送(iPad受けを廃し、自宅Mac直送へ)

| 経路 | 構成 | 遅延 | 費用 | 位置づけ |
|---|---|---|---|---|
| **C(先行導入)** | カメラ→Creators' Cloud 直接アップロード→Google Drive 自動転送→Mac の同期フォルダを bps が監視 | 数分 | **0円**(無料25GB/月100GB枠内)+テザリング | 設定だけで組める。まずこれで運用感を掴む |
| **B(本命)** | カメラ FTP 自動転送→GL.iNet ルーター(SIM)+Tailscale→自宅 Mac の FTP サーバ | **数秒〜十数秒/枚** | ルーター1〜2万円+SIM | 撮影者の操作ゼロ。試合終了時にほぼ全量着弾 |
| iPad 受信 | ShutterSnitch 等 | — | — | **不採用**(バックグラウンド制限で構造的に不適) |

- どちらの経路も**着弾先は bps の inbox/**。パイプラインは入力源を区別しない(既存設計のまま)
- カメラ設定は既存 docs/04 の FTP 節がそのまま使える(宛先が Tailnet の 100.x.x.x になるだけ)
- 旧 Phase 4(現場ノート PC+現場ルーター)は**廃止**。ハートビート通知(ntfy)は
  自宅 Mac 無人運用の監視としてそのまま有効

### レイヤー2: セレクト(既存パイプラインを 3 値運用に確定+精度強化)

**既存の bps パイプラインがそのまま中核**。強化は優先順に:

1. **Phase 1 校正(最優先・実写があれば半日)**: 実際の試合写真で `bps calibrate` →
   手動セレクトと突合し、reject_pct / keeper_pct を「★0 が 10-20%」になるよう調整。
   ネット越し・流し撮りを層別確認
2. **「わが子優先」を将来項目から本設計に昇格**: 調査で「個人向けには誰も提供していない」
   本質要件と確認。顔クラスタリング(InsightFace 系、ローカル)で「指定した子の顔クラスタ
   を含むフレームは keep_score に加点+除外基準を厳しく」。教師は「過去に自分が採用した
   写真に写る頻度」で半自動特定できる
3. **決定的瞬間(Phase 3)**: 設計済みの通り(lrcat 教師の埋め込み分類器+ポーズ/ボール補助)。
   バット付近のボール検出は実写 1 枚目で有効性を確認済み
4. **ベンチマーク**: LrC 15.2 Assisted Culling(追加費用ゼロ・スポーツ評価が向上)と
   FilterPixel DeepCull($9.99/月・スポーツ特化)を Phase 1 の突合に含め、
   自作の勝ち筋(リアルタイム・わが子・ローカル完結)を数値で確認する

### レイヤー3: 自動現像(新規 Phase 5)

段階導入。**出力は既存の XMP 書き込みに crs: タグを足すだけ**なので、
配送アーキテクチャは変更不要:

| 段階 | 内容 | 費用 | 期待値 |
|---|---|---|---|
| 5a(即日) | LrC の「基準1枚手動現像→設定同期」+Quick Develop 自動設定のバッチ運用を docs 化。★3+ スマートコレクションに対して 2 クリック | 0円 | 光が安定した昼間試合なら 8 割 |
| 5b(本命) | **DIY 現像モデル**: 自分の .lrcat から (画像, スライダー値) を抽出 → 埋め込み→回帰(sklearn。露出/WB/トーン/彩度のグローバル調整に限定)→ deliver 時に `crs:` を XMP へ併記(`AlreadyApplied=False`, `ProcessVersion` 必須)→ LR 取り込みと同時に「自分の現像」が当たっている | 0円 | グローバル調整は研究・商用実績とも十分。クロップは対象外(誤クロップ報告があり、構図は人の領分) |
| 5c(代替/比較) | Neurapix(20枚から学習、$0.03/枚)または Aftershoot EDITS($30/月)を 5b のベンチマークに | 少額 | 5b の精度目標を定める物差し |

- 5b の教師抽出は Phase 3(セレクト学習)と同じ lrcat 読み出し基盤を共用
- 製品化時は LrC Lua プラグイン(`applyDevelopSettings`)で LR 内完結 UX へ
  (Neurapix/Impossible Things が Adobe Exchange 配布の先例)。カタログ DB 直接書き込み
  (Imagen 方式)は非公開スキーマ依存のため採用しない

## 既存資産の活用判定

| 資産 | 判定 | 備考 |
|---|---|---|
| bps パイプライン(ingest/grouping/scoring/metadata/deliver、テスト173件) | **全面活用**(コア) | 入力源非依存の設計が経路B/Cにそのまま効く |
| AF 矩形による主被写体特定(M0 実機確認の成果) | **全面活用** | 空白領域の技術的裏付けそのもの |
| M4 設計(watch 常駐) | **活用**(場所が変わる) | 現場ノートPC→自宅Mac常駐(launchd)。熱・電池・盗難の制約が消え簡素化 |
| 旧 Phase 4(現場PC+現場ルーター構成) | **廃止** | 自宅直送(B)がすべての面で上回る |
| docs/04 のカメラFTP設定手順 | 活用 | 宛先IPがTailnetになるだけ |
| Phase 3 設計(lrcat 教師学習) | **活用+拡張** | 同じ基盤が自動現像 5b の教師抽出を兼ねる |
| 製品化調査(docs/05) | 活用 | 空白領域の確認により価値が上がった。「リアルタイム・わが子・ローカル完結」が差別化軸と確定 |

**捨てるものはほぼ無い。** 変わるのは「処理する場所」(現場→自宅)と、
現像レイヤーの追加だけで、どちらも既存アーキテクチャの延長線上にある。

## 検証

- R1: 混同行列(採用/除外/要確認 × 自分の判断)で「要確認 10-20%・見逃し(誤除外)ゼロ」を確認
- R2/R3: 実試合で「試合終了 → LR に並ぶまで」の遅延と、iPad での星付けが Mac に還流することを確認
- R4: 自動現像した ★3+ を自分の手現像と並べ、露出±0.3EV / WB±300K 以内の一致率を測る
- R5: 連写バーストの到達率・最悪遅延(既存 M6 リハーサル表を流用)
